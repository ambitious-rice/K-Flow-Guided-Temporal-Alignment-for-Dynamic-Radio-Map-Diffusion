# 观测平衡固定测试方案 v1

本方案用于筛选 W1 训练方法、检查噪声适应 DA 是否仍然有效，并确认最终改进能否迁移到 W16。固定配置位于：

```text
configs/evaluation/observation_balance_validation_v1.yaml
```

测试代码位于：

```text
scripts/run_observation_balance_validation.py
scripts/evaluate_observation_balance_cell.py
src/rmdm/evaluation/observation_balance_suite.py
```

## 1. 固定内容

所有候选模型必须使用同一个 YAML 文件。不得针对单个候选修改下列内容：

- 验证集和 Stage-A manifest；
- 每个场景选择的视频数；
- W1/W16 的帧起点；
- 采样率和注入噪声档位；
- DDIM steps、DA strength、guided steps 和 max update；
- dataset、mask、观测噪声和 DDIM 初始噪声 seed；
- GPU 进程数。

视频按 `scene_id` 分组后排序，每个场景始终选择排序后的前 N 个视频。mask、观测噪声和 DDIM 初始噪声都由物理帧名、采样率和固定 seed 生成。因此：

- 同一候选重复运行时使用完全相同的随机输入；
- 不同候选在同一个测试单元中使用完全相同的随机输入；
- W1 和 W16 遇到同一物理帧时使用相同的 mask、观测噪声和 DDIM 初始噪声；
- DataLoader 不 shuffle；
- 使用固定八进程运行，禁止在候选之间改变 world size；
- CUDA deterministic algorithms 开启，TF32 和 cuDNN benchmark 关闭。

## 2. 六个固定阶段

### fast_w1

用途：训练期间快速淘汰 checkpoint。

- 每个场景 1 个视频，共 3 个视频；
- W1 全部 100 帧；
- `p=1%、3%`；
- `sigma=0、0.05`；
- no-DA；
- DDIM-20；
- 共 4 个测试单元。

每 1,000 或 2,000 个训练 step 运行。连续三次没有进入可接受范围时停止该训练分支。

### full_w1

用途：只确认 fast_w1 最好的 2--3 个 checkpoint。

- Stage-A 全部 30 个视频；
- W1 全部 100 帧；
- `p=1%、2%、3%`；
- `sigma=0、0.01、0.05`；
- no-DA；
- DDIM-20；
- 共 9 个测试单元。

### w1_da_gate

用途：检查 W1 是否仍给 DA 留有修正空间。

- Stage-A 全部 30 个视频；
- `p=1%、3%`；
- `sigma=0.01、0.05`；
- 运行使用真实注入方差的 known-noise DA；
- 共 4 个测试单元；对应 no-DA 结果直接使用 `full_w1`，不重复计算。

这里只用真实注入噪声方差，隔离“模型是否响应 DA”这一问题，不在 checkpoint 筛选中运行噪声估计器。

### fast_w16

用途：W16 训练期间检查 W1 改进是否成功迁移。

- 每个场景 1 个视频；
- 窗口起点固定为 `0、32、64`；
- `p=1%、3%`；
- `sigma=0、0.05`；
- no-DA；非零噪声同时运行 known-noise DA；
- DDIM-20。

### full_w16

用途：确认最终 1--2 个 W16 checkpoint 的基础生成性能。

- Stage-A 全部 30 个视频；
- 窗口起点 `0、16、32、48、64、80`，覆盖前 96 帧；
- `p=1%、2%、3%`；
- `sigma=0、0.01、0.03、0.05`；
- no-DA；
- 共 12 个测试单元。

### w16_da_gate

用途：确认最终 W16 对噪声适应 DA 的响应。

- Stage-A 全部 30 个视频；
- `p=1%、2%、3%`；
- `sigma=0.01、0.03、0.05`；
- known-noise DA；对应 no-DA 结果直接使用 `full_w16`；
- 共 9 个测试单元。

W16 的窗口级噪声估计和 estimated-noise DA 只在 W16 checkpoint 完全确定以后运行。它不参与 checkpoint 排名；先通过 `w16_da_gate`，再使用已有的 W16 噪声估计流程重新校准并进行最终下游验证。

## 3. 指标和筛选规则

所有单元输出：

- full-image MSE/NMSE/MAE/PSNR；
- unobserved-free-space MSE/NMSE/MAE/PSNR；
- observed-point MSE/NMSE/MAE。

主指标固定为 `unobserved_free_space.nmse`。

W1 必须同时满足：

1. 干净 `p=1/2/3` 平均主指标相对原 W1 至少改善 10%；
2. `sigma=0.05` 平均主指标相对原 W1 的退化不超过 2%；
3. `sigma=0.05` 的 known-noise DA 平均改善至少 2%；
4. DA 在每个测试采样率上都必须改善。

W16 必须同时满足：

1. 干净平均主指标不得低于当前 W16；
2. `sigma=0.05` 平均主指标相对当前 W16 的退化不超过 2%；
3. known-noise DA 平均改善至少 2%；
4. DA 在每个测试采样率上都必须改善。

通过门槛后，按干净条件下的平均主指标选择最低者。差距小于 1% 时视为相当，选择更早的 checkpoint。

## 4. 本地准备命令

W1 基线与候选分别准备一次。`candidate-id` 是结果目录名，不参与随机数生成。

```bash
python scripts/run_observation_balance_validation.py prepare \
  --suite configs/evaluation/observation_balance_validation_v1.yaml \
  --variant w1 \
  --candidate-id original_w1 \
  --config configs/hvdit_v4_x0_w16_ratebalanced_no_tx/w16_from_no_tx_w1_4gpu.yaml \
  --checkpoint /path/to/original_w1.pth \
  --manifest manifests/dynamic_sparse_v2_semantic_vehicle/val_subset_v1.json \
  --output-root runs/observation_balance_validation
```

只准备快速阶段时增加：

```text
--stages fast_w1
```

W16 使用相同命令，把 `--variant` 改为 `w16`，checkpoint 改为对应 W16，并用 `--stages fast_w16` 或完整的 W16 阶段列表。

## 5. 执行、恢复和汇总

在配置好的八 GPU 环境中执行：

```bash
python scripts/run_observation_balance_validation.py run \
  --candidate-id original_w1 \
  --output-root runs/observation_balance_validation \
  --gpus 0,1,2,3,4,5,6,7 \
  --python /data/fzj/conda_envs/RMDM_HVDIT_V2/bin/python
```

每个测试单元独立写入一个 JSON。重复执行同一命令时，已经完成的单元会跳过，未完成单元继续执行。需要重新计算全部单元时增加 `--rerun`。

汇总：

```bash
python scripts/run_observation_balance_validation.py summarize \
  --candidate-id original_w1 \
  --output-root runs/observation_balance_validation
```

候选与基线比较：

```bash
python scripts/run_observation_balance_validation.py compare \
  --suite configs/evaluation/observation_balance_validation_v1.yaml \
  --variant w1 \
  --candidate-id soft_alignment_w1_step20000 \
  --baseline-id original_w1 \
  --output-root runs/observation_balance_validation
```

汇总可以在任务尚未跑完时执行；比较要求各筛选条件所需的采样率齐全，缺失时会报错。

输出的 `passed` 是四个固定门槛的合并结果。只有 `passed=true` 的 W1 候选进入 W16 训练，只有通过 W16 门槛的候选进入窗口级噪声估计和最终验证。

## 6. 最终 W16 estimated-noise DA

这一部分只对最终一个 W16 checkpoint 执行一次，固定使用 DDIM-50、4 folds、8 members。输出目录记为 `$FINAL_ROOT`。

先在 Stage-A 干净观测上收集校准数据：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 python -m accelerate.commands.launch --multi_gpu --num_processes 8 \
  scripts/evaluate_w16_noise_estimation.py \
  --config "$MODEL_CONFIG" --checkpoint "$W16_CHECKPOINT" \
  --manifest "$VAL_MANIFEST" --subset-stage stage_a --videos-per-scene 10 \
  --starts 0,16,32,48,64,80 --rates 1,2,3,5,8,10 --noise-stds 0 \
  --ddim-steps 50 --folds 4 --members 8 --member-batch-size 2 \
  --seed 20260805 --namespace observation_balance_w16_final_v1 --mode collect \
  --output-dir "$FINAL_ROOT/calibration_units" --expected-visible-gpus 0,1,2,3,4,5,6,7
```

拟合该 W16 的校准参数：

```bash
python scripts/fit_w16_noise_calibration.py \
  --units-dir "$FINAL_ROOT/calibration_units/units" \
  --output "$FINAL_ROOT/calibration.json"
```

然后在 Stage-B 产生固定噪声估计结果：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 python -m accelerate.commands.launch --multi_gpu --num_processes 8 \
  scripts/evaluate_w16_noise_estimation.py \
  --config "$MODEL_CONFIG" --checkpoint "$W16_CHECKPOINT" \
  --manifest "$VAL_MANIFEST" --subset-stage stage_b_extra --videos-per-scene 10 \
  --starts 0,16,32,48,64,80 --rates 1,2,3,5,8,10 \
  --noise-stds 0,0.005,0.01,0.02,0.03,0.05,0.075,0.10 \
  --ddim-steps 50 --folds 4 --members 8 --member-batch-size 2 \
  --seed 20260805 --namespace observation_balance_w16_final_v1 --mode evaluate \
  --calibration "$FINAL_ROOT/calibration.json" \
  --output-dir "$FINAL_ROOT/noise_estimation" --expected-visible-gpus 0,1,2,3,4,5,6,7
```

最后只对任务关心的 `p=1/2/3` 和 `sigma=0.01/0.03/0.05` 运行 estimated-noise DA：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 python -m accelerate.commands.launch --multi_gpu --num_processes 8 \
  scripts/evaluate_w16_estimated_noise_da.py \
  --config "$MODEL_CONFIG" --checkpoint "$W16_CHECKPOINT" \
  --manifest "$VAL_MANIFEST" --subset-stage stage_b_extra \
  --estimation-dir "$FINAL_ROOT/noise_estimation" \
  --output-dir "$FINAL_ROOT/estimated_noise_da" \
  --rates 1,2,3 --noise-stds 0.01,0.03,0.05 \
  --ddim-steps 50 --guided-steps 15 --strength 0.5 --max-update 0.25 \
  --videos-per-scene 10 --noise-seed 20260805 --expected-visible-gpus 0,1,2,3,4,5,6,7 \
  --estimated-noise-scales 0.85

python scripts/summarize_w16_estimated_noise_da.py \
  --units-dir "$FINAL_ROOT/estimated_noise_da/units" \
  --output "$FINAL_ROOT/estimated_noise_da_summary.json" \
  --bootstrap-draws 2000 --bootstrap-seed 20260805
```

这里的 `0.85`、DDIM-50 和最后 15 步引导保持历史正式设置，不再针对新候选重新搜索。这样最终结果只检验“新 W16 是否兼容已有噪声适应方法”。

## 7. 重复实验要求

每次实验只能变化：

- candidate ID；
- checkpoint；
- 与 checkpoint 对应的模型配置；
- 当前执行的阶段。

不能变化 YAML 中的测试集合、随机 seed、DDIM 和 DA 设置。基线与候选必须分别执行相同阶段。所有比较均从逐单元 JSON 汇总，不从训练日志抄录指标。

## 8. 本地测试环境

本地轻量测试复用 Conda 环境 `RMDM`（Python 3.11），路径为 `/data_p6/fzj/conda/envs/RMDM`。已安装 PyTorch、Diffusers、Accelerate、NumPy、SciPy、PyYAML 和 pytest。

在项目根目录运行评测与噪声估计单测：

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 PYTHONPATH=src:. \
  conda run --no-capture-output -n RMDM python -m pytest \
  tests/evaluation tests/noise_estimation -q
```

这些测试使用 CPU；真实模型的八 GPU 推理、DA 性能和实验运行仍在远程执行。
